TrackFlow — Order & Delivery Platform

Java 21 · Spring Boot 4 · Spring Cloud Gateway · Eureka · Kafka (KRaft) · PostgreSQL · Flyway · Spring Security (JWT) · Angular 22 · Leaflet · Docker

My most complete personal project: a containerized, event-driven system for managing orders from checkout to doorstep, built to practise microservices, Kafka and Docker beyond what I'd used at work. Customers place orders, riders deliver them while being tracked live on a map, and admins oversee everything. Every part runs in its own container and starts with a single docker compose up.

Browser → Nginx → API Gateway (auth + routing) → order-service / delivery-service order-service ──ORDER_CONFIRMED──► Kafka ──► delivery-service (creates the delivery) delivery-service ──status updates───► Kafka ──► order-service (mirrors the status)

Architecture

  • Database per service: order and delivery services each own their PostgreSQL schema, managed with Flyway.
  • Event-driven: services never call each other; a confirmed order becomes a delivery and every delivery update flows back to the order through Kafka.
  • Gateway + discovery: Spring Cloud Gateway routes through Eureka; the business services aren't exposed outside the network at all.

Security

  • Login built into the gateway: BCrypt passwords, signed RS256 JWTs, and real logout through token revocation.
  • Three roles: Admin, Customer and Rider. The gateway checks roles, and each service re-verifies the token and enforces ownership ("is this your order?").

Reliability

  • Events are published only after the database commit, so rolled-back changes never leak out.
  • Idempotent consumers and forward-only state machines make Kafka redelivery harmless.
  • Retries with a dead-letter topic for bad messages, and optimistic locking for concurrent updates.

Frontend

  • Angular 22 with standalone components, signals, httpResource and OnPush change detection.
  • Role-aware screens, plus live rider tracking on a Leaflet map using the browser's GPS.
